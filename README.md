Gesture recognition from accelerometer data with a small CNN, trained in
TensorFlow, optimized, quantized and run on a Raspberry Pi Pico W with a
Waveshare Pico Eval Board. Built on the IMU track of Labs 2.2, 2.3 and 2.4.

Classes: `negative` (stationary), `ring` (O), `slope` (L), `wing` (W).

## Layout

| Path | What |
|---|---|
| `hw2.ipynb` | training, experiments, results table, architecture comparison |
| `src/preprocessor.py` | load CSV, convert to g, low-pass, resample to 128, split, normalise (from Lab 2.2) |
| `data/shared/<class>/` | Lab 2.2 dataset, 25 recordings per class, used for train/val/test |
| `data/own/<class>/` | own recordings from the Pico, used only to measure own-data accuracy |
| `data_collection/` | Pico firmware that records the IMU to the SD card (from Lab 2.2, unchanged) |
| `data_collection_serial/` | same recorder, but sends each recording over USB serial (no SD card needed) |
| `tools/record_serial.py` | host side: triggers a recording and saves it to `data/own/<class>/` |
| `models/` | trained Keras models, `.tflite` files and the C array for the Pico |
| `firmware/` | Pico firmware that runs the model with TFLite Micro (from Lab 2.4) |
| `report/` | IEEE report source |

## Data format

Each recording is a CSV file with an `ax,ay,az` header and raw ICM-20948
accelerometer counts (16384 counts = 1 g). The preprocessor expects about
2.1 s per file at 2000 Hz (about 4200 rows, +/-5 %).

The shared dataset was recorded with the board screen facing down: x right,
y backward, z up. The own recordings were made with the board held upright
(gravity on -x), gestures drawn in the board's x-y plane. `ROTATION` in the
notebook maps them to the shared frame: shared x = own z, shared y = own y,
shared z = -own x.

## Training (PC)

Uses the course Python environment (TensorFlow 2.x, NumPy, SciPy, pandas,
matplotlib). From this directory:

```sh
jupyter notebook hw2.ipynb
```

Run all cells. Output:

- `report/architecture_table.csv`: Step 6 comparison

- `models/*.h5`: Keras models; `models/own_gap_int8.tflite`: int8 model for the Pico

## Recording own data (Pico)

No SD card was available, so own data is recorded with
`data_collection_serial/`: the same accelerometer data as the lab's
`data_collection/` (raw counts, `ax,ay,az`), sampled at a fixed 2000 Hz for
2.1 s (4200 rows), buffered in RAM and sent over USB serial after each
recording. The original SD version is kept unchanged in `data_collection/`.

Build and flash (inside the course Docker image, from the repository root):

```sh
cd hw2/data_collection_serial && mkdir -p build && cd build
cmake .. && make -j4
picotool load main.uf2 -f -x
```

Record on the host (needs `pyserial`), from `hw2/`:

```sh
python tools/record_serial.py --ping        # connection check
python tools/record_serial.py ring -n 5     # writes data/own/ring/own_<time>.txt
```

LED: dim white idle, blue 1 s get ready, green 2.1 s do the gesture, yellow
sending. After each recording the script asks keep / redo / quit.

## Running on the Pico

`firmware/` runs the chosen model (own GAP model, lr 1e-2, int8) with TFLite
Micro. The preprocessing in `src/data_preprocessor.cpp` follows
`src/preprocessor.py` step by step; its constants, the model and the own
recordings are generated by `tools/export_firmware.py`.

```sh
python tools/export_firmware.py          # on the host, after hw2.ipynb
# inside the course Docker image:
cd hw2/firmware && mkdir -p build && cd build
cmake .. && make -j8 main own_data_test
picotool load own_data_test.uf2 -f -x    # or main.uf2
python tools/serial_log.py 60            # on the host, from hw2/
```

Targets:

- `own_data_test`: runs the 20 own recordings stored in flash, prints one line
  per gesture and a summary. Expected output (saved in
  `firmware/own_data_pico_output.txt`, PC result in
  `firmware/own_data_reference.txt`):

  ```
  Own data test
  Model: 5520 bytes, tensor arena used: 5076 of 6144 bytes
  own_20261104_200029.txt true=negative pred=negative input_sum=55504
  ...
  Pico accuracy: 15/20
  Average per gesture: preprocessing 311.80 ms, inference 14.471 ms
  ```

- `main`: live recognition. LED blue 1 s (get ready), green 2.1 s (do the
  gesture, board held upright as for the own recordings), yellow
  (processing), then the class colour for 2 s: negative dim white, ring
  magenta, slope cyan, wing white. Serial output per gesture:

  ```
  Predicted: wing  (negative 0.00, ring 0.00, slope 0.10, wing 0.90)
  Preprocessing 306.1 ms, inference 14.43 ms
  ```
